# パケット攻防ラボ

情報処理安全確保支援士の範囲で、通信への攻撃と対策をパケット単位で図解する学習サイトです。
正常な通信の流れの上に、攻撃がどこで割り込み、どの対策がどこで止めるのかを重ねて見られます。

## 教科書

`/book` に、全21章（7部）の教科書があります（`src/book/`）。最初の章「情報セキュリティとは」で、機密性・完全性・可用性と、
真正性・責任追跡性・否認防止・信頼性を学びます。ほかの章はシナリオと1対1で対応します。
節ごとに短い本文と専用の図を積み重ねて読み進めます。図は3種類です。

| 図 | 内容 |
| --- | --- |
| シーケンス図（`seq`） | だれとだれが、どの順にやり取りするか |
| パケットの構造（`layers`） | 見出し（ヘッダ）の並び。変換や暗号化の前後を行で比べる |
| 構成図（`map`） | 機器の配置とつながり、通す・止める通信 |

その節で新しく加わった要素には `add: true` を付け、図の中で黄色の印で示します。各節から、
対応するシナリオの図解の場面（`see`）へ移れます。テストで、図の参照や図解へのリンクが正しいかを確かめています。

## 基礎編

攻撃の前に、ふだんの通信の仕組みだけを学ぶ短いレッスンです（正常のモードだけ。シナリオに `basic: true` を書く）。
新人研修の最初の教材としても使えます。

| レッスン | 内容 |
| --- | --- |
| パケットとは | パケットへの分割、カプセル化、MACアドレスとIPアドレスの違い |
| IPアドレスとポート | プライベートIPアドレス、NAPT、代表的なポート番号 |
| TCPとUDP | 3ウェイハンドシェイク、番号と再送、UDPの手早さ |
| DNSとHTTPSの仕組み | キャッシュDNSと権威DNS、TTL、TLSのハンドシェイクとサーバ証明書 |
| FWとDMZ | FWのルール、DMZ、ステートフルインスペクション |

各ステップには「ひとことで」の説明（`src/plain/`）があり、「やさしく」と「くわしく」を切り替えられます。

## シナリオ

| シナリオ | 攻撃 | 主な対策 |
| --- | --- | --- |
| 電子署名と公開鍵 | 改ざん、公開鍵のすり替え | 電子署名、電子証明書（PKI） |
| DNS名前解決 | キャッシュポイズニング（カミンスキー型） | 再帰問合せの制限、送信元ポートのランダム化、DNSSEC |
| HTTPS（TLS 1.3） | 中間者攻撃 | 証明書の検証、HSTS |
| メール送信 | 送信元なりすまし（BEC） | SPF、DKIM、DMARC |
| Webセッション | CSRF | CSRFトークン、SameSite属性 |
| Web掲示板 | XSS（格納型） | 出力時のエスケープ、CSP、HttpOnly属性 |
| Webアプリとデータベース | SQLインジェクション | プレースホルダ、WAF、DBアカウントの最小権限、ソルト付きハッシュ |
| シングルサインオン（SAML） | アサーションの偽造 | 署名・Audience・有効期限の検証、IdPとSPのログの突き合わせ |
| 社内LAN | ARPスプーフィング | DAI、DHCPスヌーピング、静的ARPエントリ |
| 社内の無線LAN（IEEE 802.1X） | 偽APによる認証情報の窃取 | サーバ証明書の検証、EAP-TLS、WPA3（PMF・SAE）、WIPS |
| プロキシ経由のWeb閲覧 | 標的型攻撃（C&Cサーバ、横展開、持ち出し） | プロキシ認証、URLフィルタ、特権IDの管理、EDR、ログの監視 |
| DNS（UDP） | DNSリフレクション（DDoS） | オープンリゾルバの解消、RRL、イングレスフィルタリング、DDoS対策サービス |
| テレワーク（IPsec VPN） | VPNからの侵入 | クライアント証明書、多要素認証、脆弱性の修正 |
| クラウドストレージ | 設定ミスによる公開 | パブリックアクセスのブロック、CSPM、期限付きURL、アクセスログ |
| ソフトウェアの更新 | サプライチェーン攻撃（更新の改ざん） | コード署名の検証、署名の鍵の保護（HSM）、段階的な適用、資産の一覧 |

シナリオは `src/scenarios/` に1ファイルずつあります。登場人物（`actors`）に書いた id だけを
ステップの `from` / `to` に使えるので、書き間違いは型チェックで見つかります。

## 表示モード

| モード | 内容 |
| --- | --- |
| 正常 | ふだんの通信が、どの機器をどの順に通るか |
| 攻撃 | 攻撃者がどこにいて、どのステップに割り込むか |
| 対策 | どの機器のどの仕組みで、攻撃が止まるか |
| 事後対応 | 攻撃が成功したあと、CSIRTが 検知 → トリアージ → 封じ込め → 証拠保全 → 根絶・復旧 → 報告 → 再発防止 の順に、どの機器で何をするか |

事後対応のステップには `phase`（段階）を書きます。CSIRTは構成図の社内LANの席（`soc`）に置き、
ケーブルではなく点線で、機器との連絡や指示を表します。

## ステップの再生

画面の上に、モードのステップを「流れ」として並べ、いまどこにいるかを示します。
その下で、構成図と「このステップで起きていること」を見ながら1ステップずつ進めます。
パケットの層、機器の中の状態、シーケンス図、論点は「詳しく見る」で開きます（開いた項目は覚えておきます）。

再生すると、パケットが機器に着くたびに止まり、そこで何が起きているかを説明します（速さは3段階）。
ステップごとに、次の内容を書いています。

| 項目 | 内容 |
| --- | --- |
| `send` | 送信元で何をするか |
| `via` | 経由する機器（FW、インターネット、L2スイッチなど）で何が起きるか。書かなければ既定の説明 |
| `receive` | 宛先で何が起きるか（阻止されるステップでは、止めた機器で何をするか） |
| `wire` | パケットの層（Ethernet、IP、TCP・UDP、TLS、トンネル）と、注目する層 |
| `changes` | 機器の中の状態（ARPテーブル、DNSのキャッシュなど）の変化。`at` で、変わる機器を指定できる |

状態の表は、シナリオの `states` に書きます。テストで、`via` や `at` に書いた機器が実際の経路の上にあるかを確かめています。

## まとめと確認問題

`src/learning/` に、シナリオごとの学習の手引きと確認問題をまとめています。

- まとめ：学習目標、前提となる知識、よくある誤解、対策の比較表、午後の問題文の手がかり、論点
- 確認問題：午前の形式（4択）と、午後の形式（字数制限つきの記述。解答例と採点のポイントつき）

テストで、記述の解答例が字数の上限に収まっていることと、4択の正解の記号が偏っていないことを確かめています。
答えはどこにも保存しません。

## 解説ページ

通信の図にしにくい分野は、`src/topics/` に解説ページとしてまとめています（`/topics/risk` など）。

| ページ | 内容 |
| --- | --- |
| リスクマネジメント | リスクアセスメント（特定・分析・評価）、リスク対応（低減・回避・移転・受容）、残留リスク、ISMS |
| CSIRTの体制と外部機関 | CSIRTの役割、平時の準備、JPCERT/CC・IPA・警察・個人情報保護委員会・国家サイバー統括室、ISACなどの情報共有 |
| 脆弱性管理とPSIRT | CVE・CVSS・JVN、修正の優先度、早期警戒パートナーシップ（届出）、PSIRT、SBOM |
| クラウドのセキュリティ | 責任共有モデル、設定ミスとCSPM・CASB、ISMAP、クラウドのインシデント対応 |
| セキュリティ関連の法令 | 不正アクセス禁止法、個人情報保護法（漏えい等報告）、刑法のサイバー犯罪、営業秘密、そのほかの法令 |
| 監査と内部統制 | システム監査の流れ、監査人の独立性、監査証拠と監査調書、IT全般統制・IT業務処理統制 |

どのページにも、学習目標、午後の問題文の手がかり、確認問題、関連するシナリオへのリンクがあります。
文中の用語を押すと説明が開き、その用語が出てくる図解のステップへ移動できます。
法令や組織など変わりうる情報には、いつの時点の情報かと、参考にした資料を書いています。

## 用語一覧

`src/glossary/terms.ts` に用語と説明をまとめています。`aliases` に書いた文字列がステップの説明に出てくると、
自動でその用語として扱われ、次のように連動します。

- 用語一覧の用語を押すと、その用語が出てくるステップへ移動する（もう一度押すと次の登場箇所へ）
- ステップを進めると、そのステップに出てくる用語が一覧で強調される
- 説明文の中の用語を押すと、その用語の説明が小さく開き、出てくるステップや解説ページへ移動できる

表示している状態はURL（`/dns?mode=defense&step=2&term=dnssec` など）に反映されるので、そのまま共有できます。

## 開発

Node.js 22 と、corepack で有効にした pnpm を使います。

```sh
corepack enable
pnpm install
pnpm dev        # 開発用サーバ
pnpm verify     # 型チェック・テスト・ビルド・セキュリティチェックをまとめて実行
```

## セキュリティの設計

サイトそのものも、支援士の論点に沿って守っています。

| 対策 | 防ぐもの |
| --- | --- |
| サーバ・データベース・ログインのない静的サイト | SQLインジェクション、サーバの脆弱性の悪用、情報漏えい |
| Reactの自動エスケープだけで表示し、`dangerouslySetInnerHTML` などを禁止（CIで検査） | XSS |
| CSPで、スクリプトもスタイルもフォントも自サイトからだけ読み込む | XSS、外部CDNの改ざん |
| HSTS、`frame-ancestors 'none'`、`nosniff` などのヘッダ（`public/_headers`） | 中間者攻撃、クリックジャッキング、MIMEタイプの誤認 |
| 公開から7日未満のパッケージを入れない、許可したもの以外のインストールスクリプトを止める（`pnpm-workspace.yaml`） | サプライチェーン攻撃 |
| GitHub Actions をコミットSHAで固定し、権限は読み取りだけ | CIの乗っ取り |
| mainブランチはPR経由でのみ変更 | 確認されていない変更の公開 |
| `security.txt` と `SECURITY.md` で連絡窓口を用意 | 脆弱性が報告されないまま放置されること |

## 公開

Cloudflare Workers の静的アセット配信を使います（`wrangler.jsonc`）。mainブランチに反映されると、
Cloudflare 側のGit連携で自動的にビルドとデプロイが行われます。
