# パケット攻防ラボ

情報処理安全確保支援士の範囲で、通信への攻撃と対策をパケット単位で図解する学習サイトです。
正常な通信の流れの上に、攻撃がどこで割り込み、どの対策がどこで止めるのかを重ねて見られます。

## シナリオ

| シナリオ | 攻撃 | 主な対策 |
| --- | --- | --- |
| DNS名前解決 | キャッシュポイズニング（カミンスキー型） | 再帰問合せの制限、送信元ポートのランダム化、DNSSEC |
| HTTPS（TLS 1.3） | 中間者攻撃 | 証明書の検証、HSTS |
| メール送信 | 送信元なりすまし（BEC） | SPF、DKIM、DMARC |
| Webセッション | CSRF | CSRFトークン、SameSite属性 |

シナリオは `src/scenarios/` に1ファイルずつあります。登場人物（`actors`）に書いた id だけを
ステップの `from` / `to` に使えるので、書き間違いは型チェックで見つかります。

## 開発

Node.js 22 と、corepack で有効にした pnpm を使います。

```sh
corepack enable
pnpm install
pnpm dev        # 開発用サーバ
pnpm verify     # 型チェック・テスト・ビルド・セキュリティチェックをまとめて実行
```

## セキュリティの設計

サイトそのものも、支援士の論点に沿って守っています。

| 対策 | 防ぐもの |
| --- | --- |
| サーバ・データベース・ログインのない静的サイト | SQLインジェクション、サーバの脆弱性の悪用、情報漏えい |
| Reactの自動エスケープだけで表示し、`dangerouslySetInnerHTML` などを禁止（CIで検査） | XSS |
| CSPで、スクリプトもスタイルもフォントも自サイトからだけ読み込む | XSS、外部CDNの改ざん |
| HSTS、`frame-ancestors 'none'`、`nosniff` などのヘッダ（`public/_headers`） | 中間者攻撃、クリックジャッキング、MIMEタイプの誤認 |
| 公開から7日未満のパッケージを入れない、許可したもの以外のインストールスクリプトを止める（`pnpm-workspace.yaml`） | サプライチェーン攻撃 |
| GitHub Actions をコミットSHAで固定し、権限は読み取りだけ | CIの乗っ取り |
| mainブランチはPR経由でのみ変更 | 確認されていない変更の公開 |
| `security.txt` と `SECURITY.md` で連絡窓口を用意 | 脆弱性が報告されないまま放置されること |

## 公開

Cloudflare Workers の静的アセット配信を使います（`wrangler.jsonc`）。mainブランチに反映されると、
Cloudflare 側のGit連携で自動的にビルドとデプロイが行われます。
